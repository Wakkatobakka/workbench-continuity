# Build Workbench

The source contains the existing Workbench engine/UI and native signer. The public integration adds runtime loading and reuses the public Build Capsule setup. No private runtime is needed to read or assemble this repository.

With Python 3.10+:

```sh
python3 tools/build_standalone.py
```

This produces `dist/Workbench_Continuity_v1.2.0_PUBLIC.html`, the identical `android/assets/index.html`, and the SDK-free first-time setup ZIP. It verifies the vendored public inventory before assembly.

For an Android build, use the API 35 / Linux Build Tools 35.0.0 SDK generated by the included setup. Extract that generated runtime outside this source tree. The host needs Linux x86_64, Python 3.10+ and JDK 17+. On Linux, the included `vendor/android-build-capsule/abc.py fetch-runtime --output /your/new/private-runtime --accept-sdk-license` is an alternative **only after the person doing setup reads and chooses to accept Google's agreement**. The Windows maker displays it before downloading.

The public signing library is included and pinned. Verify it with:

```sh
python3 tools/prepare_signing_library.py
```

It uses the published `com.android.tools.build:apksig:8.6.1` artifact unchanged under Apache-2.0, rather than recovering a signing library from owner-private SDK carriers. Its historical local filename stays `apksig-35.0.0.jar` for build compatibility.

Keep your release keystore outside this repository. Set its password in `CONTINUITY_OWNER_PASSWORD` privately, then run:

```sh
python3 tools/build_android.py --sdk /your/runtime/runtime/sdk \
  --project android --output /your/new/build-folder \
  --keystore /your/private/keystore.p12 --key-alias YOUR_ALIAS \
  --password-env CONTINUITY_OWNER_PASSWORD
```

For a public release update, use the maintainer's same public-release key and package, and increase versionCode. A build signed with a different key cannot update the released public app. The public package is `dev.wakka.continuity.publicv12`, version 1.2.0, versionCode 3, minSdk 28, targetSdk 35. Java activity package names remain unchanged and the manifest names them explicitly.

SDK-free workflow checks:

```sh
node tests/signing-contract.test.js
node tests/runtime-roundtrip.test.js
python3 signing-tests/privacy-boundary-test.py
```

Host signing checks using your generated SDK:

```sh
python3 signing-tests/run-signing-tests.py --sdk /your/runtime/runtime/sdk
```

To check the actual emitted Claude and Grok carriers and build the current example through both, set `CONTINUITY_TEST_RUNTIME` to your generated runtime ZIP and `CONTINUITY_TEST_OUTPUT` to a private scratch directory, then run `node tests/runtime-roundtrip.test.js`. Without that variable, the same test uses an explicit SDK-free fixture and makes no compilation claim. Test outputs and generated carriers belong outside the public source.
